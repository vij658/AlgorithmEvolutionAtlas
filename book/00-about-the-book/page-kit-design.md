# Page kit design: how a chapter becomes a page

**Status:** designed, mostly not built. `expand.py` is done and tested on [AddingTwoNumbers.java](../../code/chapter-01-adding-two-numbers/AddingTwoNumbers.java). The chapter builder (`build_book.py`) is not written. The existing catalog builder ([build_html.py](../../code/tools/build_html.py)) is the starting point and already gives light and dark themes, phone-width layout, highlighted code with copy buttons, and downloadable programs.

## Goals

- A chapter is one self-contained HTML page: readable on a phone, in light and dark mode, printable.
- Every number on the page comes from a program's output; every code block is copied verbatim from a tested program; every citation points at a source with a link. The build fails when any of these is missing.
- The devices (pause-and-try, wrong turn, scene, ⊕, full circle, key idea, prove it) have a consistent look so the reader learns to recognize them.

## What exists

- **`expand.py`** (in [tools](../../code/tools/README.md)): a line `@@ AddingTwoNumbers.java: value addColumns` expands to a fenced Java block copied verbatim from that member of the tested program, de-indented. A range `first..last` works too; a comment directly above a member comes with it; banner comments do not. Tested on five directives against `AddingTwoNumbers.java`. It reports the widest line of each block. *Finding:* the chapter 1 program's displayed lines run up to 193 characters (long Javadoc and trailing comments), so the comments need re-wrapping to about 100 columns before the chapter is built.
- **`build_html.py`:** Markdown with a meta block to a catalog page, with `Verified` / `Pitfall` callouts, tables, a table of contents, and a "full verification programs" section with downloads.

## What is designed but not built

### Markdown syntax for the devices

```
::: pause Pause and try
Question text.
::: answer Show the answer
Answer text, hidden until clicked.
:::
:::
```

Container kinds: `pause`, `answer` (renders as `<details>`), `wrong` (Wrong turn), `scene` (Time travel, always labelled *reconstructed*), `combine` (the ⊕ line), `circle` (Full circle), `key` (Key idea), `prove` (Prove it). Containers nest. Each container is rendered separately by the Markdown engine, so there is no reliance on HTML-inside-Markdown parsing.

### Source labels

`[[documented]]`, `[[conjecture]]`, `[[reconstructed]]`, `[[myth]]` become small coloured chips with a one-line explanation on hover. A legend near the top explains them.

### Citations

`[@key]` becomes a superscript number linking to the Sources list. The sources are defined once in a `::: sources` block (`key | title | url | what it supports`). The list is numbered in order of first use, and the build fails on a citation with no definition or a definition never cited.

### Numbers

`{{key}}` is replaced from values parsed out of the program's printed output (for example the average longest carry chain at 40 bits). The build fails on any unresolved key, so a page cannot drift from its program.

### Figures

`@@fig name | caption` inserts an inline SVG generated by a small function, themed with the page's colour variables so dark mode works. Planned for chapter 1:

1. **Tally strokes:** 13 and 14 strokes ungrouped, then grouped in fives with the diagonal strike.
2. **The counting board, two panels:** after the push (17 pence, 22 shillings, 5 pounds, with the bunches of 12 and 20 highlighted) and after the settle (5, 3, 6, with the exchanged counters ringed).
3. **Ripple:** 99999 + 1 with a step number under each column.
4. **Lookahead reach:** what the top column of an 8-column number knows after rounds 0, 1, 2, 3 (1, 2, 4, 8 columns).

### Look and feel

A warm paper background and a serif body for long reading; dark mode; one colour per device (blue for pause-and-try, orange for wrong turn, sepia and dashed for time-travel scenes, green for key idea); a hero with the "chain of needs" as cards (vertical on phones); a reading-time estimate; collapsible answers; a timeline table with the source labels as a column; the full program and its printed output downloadable at the end.

### Build-time checks

- Every `@@` directive resolves; every `{{key}}` resolves; every `[@key]` resolves.
- No horizontal scroll at 390 px; no console errors; every internal anchor exists.
- Code line widths reported; any above 100 columns flagged.
- Screenshots at desktop-light, desktop-dark and phone widths, which I look at before sending.
- A final cross-check of the page's numbers against the program output.
